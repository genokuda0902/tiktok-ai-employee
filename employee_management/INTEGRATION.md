# Employee management integration contract (PR #17; NOT DEPLOYED)

## Boundary
Only the backend may instantiate `Registry` or call `bootstrap_admin`, `register`, `bind_identity`, `set_generation_result`. Never expose raw `actor_id` methods over HTTP, Forms or GAS. All user operations enter `AuthenticatedService` with a Google ID token cryptographically verified using `GoogleVerifier(GOOGLE_OAUTH_CLIENT_ID, optional_hosted_domain)`; verification checks signature, expiry, audience, issuer, email_verified and Google `sub`. Install and pin `google-auth` before deployment. `GOOGLE_OAUTH_CLIENT_ID` belongs in protected deployment configuration, not GitHub source or Sheets. Tokens/passwords are never persisted. The host must implement TLS, secure HttpOnly SameSite cookies if sessions are used, CSRF protection, rate limits, authenticated file downloads, and safe logs. No host or real Google login is deployed yet.

## Enrollment
Untrusted form data may only call `Registry.register(employee_id, email)` through a trusted registration handler, creating `pending` (unique ID/email, case-insensitive). A verified admin approves via `AuthenticatedService.decide(token, employee_id, 'approved')`; the admin links an independently verified Google identity using `assign_identity(admin_token, employee_id, employee_google_id_token)`. This current identity-link method requires an administrator to handle the employee's short-lived ID token and is **NOT suitable for production**; replace with a one-time server-held invitation + direct employee Google sign-in, verify the token email matches the approved record, and bind `sub` atomically. Do not ask employees to share tokens with admins. Bootstrap requires an offline trusted admin Google `sub`; never expose bootstrap as an endpoint.

## Team ② job contract
Request: authenticated `AuthenticatedService.request(employee_token, account_id)` -> `job_id` UUID hex; database owns immutable `employee_id`, `account_id`, status=`requested`. Engine may read an authenticated, internal queue message `{job_id, employee_id, account_id}`. Engine callback must be separately authenticated (service-to-service identity or signed message, replay protection); **not implemented**. A trusted backend adapter then calls `Registry.set_generation_result(admin_id, job_id, status, artifact_ref)`; raw admin ID must never be accepted from an external callback. `ready` requires approved artifact reference and QA gate; this gate is not yet connected.

## Team ④ manual-post contract
`AuthenticatedService.posting_context(employee_token, job_id)` returns `{job_id, employee_id, account_id, status, manual_post_only: true}` after verifying current approval and owner/admin rights. `video(token, job_id)` and `history(token, employee_id)` enforce access server-side. `review(token, job_id, 'posted', manual_tiktok_url)` records only a URL for a previously `ready` job; it does not upload or publish anything. The host must never serve `artifact_ref` directly without a fresh authorization check, and must use short-lived authorized download links if applicable.
